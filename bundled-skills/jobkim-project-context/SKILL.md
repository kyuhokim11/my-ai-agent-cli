# Project Context

목표는 기록량이 아니라 사람과 에이전트가 적은 탐색으로 작업을 이어갈 수 있게 하는 것이다. 실제 기록은 대상 프로젝트가 소유한다.

## 시작과 재개

1. 현재 저장소·작업 범위와 적용 지침을 확인한다. 이미 프로젝트 조사를 수행했다면 그 결과를 재사용하고 같은 조사를 반복하지 않는다.
2. README나 범위별 지침에서 기록 안내를 찾고 목표·구조·결정·활성 작업의 실제 원본 위치를 확인한다. 기존 안내의 경로를 따르며 관련 기록만 읽는다.
3. 작업 상태와 근거를 실제 코드·설정·Git 상태와 대조한다. 사용자 보고, 직접 확인, 추정을 구분한다. 코드는 현재 구현의 근거이고 승인된 요구는 의도의 근거이므로 불일치를 임의로 해소하지 않는다.
4. 현재 단계, 미완료·미검증 사항, 첫 행동을 정리한다. 기록된 다음 행동이나 과거 승인은 새 실행 권한이 아니다.

## 구조 선택

기존 파일·절·이슈가 역할을 충족하면 재사용한다. 새 체계가 필요하거나 구조 변경을 요청받으면 [구조 예시](references/structure.md)를 읽고 필요한 부분만 제안한다. 새 체계 도입과 기존 문서 이동·통합은 승인 후 수행한다. 경로나 원본이 불분명하면 확인하고, 기본 경로가 없다고 중복 생성하지 않는다.

실제 기록을 교체 가능한 `.ai-core/`나 `.agents/skills/`에 두지 않는다. Git 추적·공개 범위는 프로젝트 정책을 따르며 이 스킬 자체는 Git·게시 권한을 부여하지 않는다.

## 갱신과 피드백

- 승인된 변경 작업에 직접 필요한 기록만 갱신한다. 읽기 전용 요청은 별도 저장 요청 없이 파일을 변경하지 않는다.
- 중요한 결정, 구현 변화, 검증 결과, 장애물 시점에 체크포인트를 남긴다. 모든 명령·대화·저장 이벤트를 기록하지 않고 같은 작업 단위의 반복 수정은 묶는다.
- 새 작업 기록이 필요하면 [기록 예시](references/records.md)를 참고한다. 기존 형식이 충분하면 바꾸지 않는다.
- 현재 상태는 상단에, 그 상태에 이른 중요한 변화는 시간순 이력에 둔다. 작업 시점·시간대, 신규/변경 구분, 이유와 근거 링크를 사람이 읽을 수 있게 한다. 모르는 과거 시각을 만들지 않고 작업 시각과 기록 시각이 다르면 구분한다.
- 변경이 영향을 주는 원본만 갱신하고 작업 기록에서 참조한다. 실패한 검증은 남은 작업과 다음 행동에 반영한다. 설계 변경이 필요하면 제안으로 남기고 승인을 받는다.
- 미반영 항목은 사유와 다음 행동을 남긴다. 대체된 결정은 이전 이유와 대체 관계를 보존한다. 모든 문서를 서로 연결하거나 같은 설명을 복제하지 않는다.
- 병렬 작업은 작업별 기록을 사용하고 공용 문서는 수정 직전에 다시 읽어 다른 변경을 보존한다.

## 종료와 인계

현재 범위의 결과·검증·미해결 사항·다음 행동을 실제 근거에 맞춰 정리한다. 구현, 테스트, 커밋, 푸시, 배포는 각각 확인하고 해당하지 않는 항목은 생략한다. 커밋을 근거로 쓸 때 미커밋 변경도 구분한다.

저장 결과와 관련 링크를 확인한다. 저장 실패·끊어진 링크·접근할 수 없는 외부 기록은 한계로 보고하고 읽거나 반영했다고 주장하지 않는다. 인증 정보나 민감한 원문 로그는 기록하지 않는다. 오래된 기록을 임의로 삭제하지 않는다.

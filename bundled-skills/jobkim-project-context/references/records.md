# 필요한 기록만 남기는 예시

기존 형식이 있으면 유지한다. 아래 항목은 필요한 경우에만 사용하며 미정 내용을 추정해 채우지 않는다.

## 작업 기록

- 목표·범위와 제외 범위
- 관련 목표·구조·결정 원본 링크
- 마지막 확인 시점과 시간대, 저장소·브랜치 등 확인 범위
- 현재 상태: 계획 / 진행 / 차단 / 검증 대기 / 완료
- 진행 흐름: 완료한 단계 / 현재 단계 / 남은 단계
- 현재 사실, 근거, 사용자 보고와 미확인 사항
- 검증: 목적 / 명령·방법 / 결과 / 미검증 범위
- 다음 행동과 필요한 승인
- 관련 있는 경우만 커밋·푸시·게시 각각의 확인 결과

중요한 변화는 다음처럼 묶어서 시간순으로 기록한다.

| 작업 시점·시간대 | 구분 | 내용과 이유 | 원본·근거 링크 | 반영 상태 |
|---|---|---|---|---|
| 확인한 날짜·시간 | 신규 / 변경 / 결정 / 검증 / 정정 | 다음 작업자가 알아야 할 변화 | 관련 파일·절 | 반영 완료 또는 미반영 사유·다음 행동 |

시간을 모르면 날짜와 시간 미확인을 적는다. 뒤늦게 기록하면 작업 시점과 기록 시점을 구분한다. 완료는 합의한 작업 범위와 검증 기준을 충족한 상태이지 게시까지 끝났다는 뜻이 아니다. 차단은 해소에 필요한 입력을, 검증 대기는 남은 확인을 명시한다.

## 결정 기록

제목, 상태(제안·채택·대체), 맥락, 선택과 이유, 주요 대안, 영향, 관련 작업 링크를 남긴다. 중요한 결정에만 별도 기록을 만들며, 대체할 때 과거 이유를 지우지 말고 새 결정으로 연결한다.

검증 결과가 가정과 다르면 작업 상태와 다음 행동을 먼저 정정하고 필요한 설계 변경을 제안한다. 승인 후 결정 원본과 실제 구조 원본을 갱신하며 작업 기록은 링크로 연결한다.

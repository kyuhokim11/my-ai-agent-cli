# AI 개발 시스템 전략과 이 프로젝트의 역할

## 문서 목적

이 문서는 개인 AI 개발 시스템의 전체 방향과 `my-ai-agent-cli`의 위치를 정의한다. 현재 존재하는 구현 프로젝트는 이 저장소뿐이므로 전체 개념도 여기에서 임시로 관리한다. 향후 각 개념이 별도 프로젝트로 만들어지면 전체 전략은 상위 전략 저장소로 이전하고, 이 문서에는 이 프로젝트의 책임과 연계 계약만 남긴다.

## 전체 목표

파운데이션 모델을 직접 학습시키는 대신, 성능이 검증된 모델에 작업 규칙, 전략, 스킬과 실제 프로젝트 맥락을 필요한 시점에 제공하여 일관된 개발 품질을 재현한다.

이 시스템에서 성장하는 것은 모델 가중치가 아니라 다음 지능 자산이다.

- 작업 원칙과 안전 경계
- 프로젝트를 조사하고 변경하는 절차
- 반복 작업을 해결하는 재사용 스킬
- 기술적 의사결정과 실패에서 얻은 교훈
- 완료 여부를 판단하는 검증 기준
- 프로젝트와 조직의 도메인 지식
- 작업에 필요한 컨텍스트를 선택하는 방법

## 전체 개념 구조

```text
전략·거버넌스
  목표, 경계, 로드맵, 품질 기준
        ↓
컨텍스트 배포
  규칙과 스킬을 에이전트 워크스페이스에 설치
        ↓
프로젝트 지식
  코드, 문서, 설정, API 계약, 프로젝트 전용 지침
        ↓
에이전트 실행 환경
  Codex, Gemini CLI, Antigravity와 향후 도구
        ↓
파운데이션 모델
  작업에 적합한 외부 모델
        ↓
평가와 개선
  결과 검증, 교훈 선별, 지능 자산 갱신과 재배포
```

각 계층은 독립적으로 교체할 수 있어야 한다. 특정 모델이나 에이전트가 바뀌어도 규칙과 스킬의 의미가 유지되어야 하며, 배포 도구가 전체 전략이나 프로젝트 고유 지식을 독점해서는 안 된다.

## 현재 프로젝트

### 정체성

- 저장소: `my-ai-agent-cli`
- npm 패키지: `@jobbykim/ai-init`
- 역할: AI 에이전트 컨텍스트 배포 및 프로젝트 초기화 CLI

이 프로젝트는 개인 AI 개발 시스템 전체가 아니다. 검토된 공통 규칙과 스킬을 패키징하여 여러 컴퓨터와 프로젝트의 에이전트 워크스페이스에 안전하게 전달하는 실행 구성요소다.

### 목적

1. 같은 버전의 자체 규칙, 초기화 정책과 자체 스킬을 어디서든 재사용한다.
2. 신규 프로젝트에는 과잉 설계를 억제하는 시작 원칙을 적용한다.
3. 기존 프로젝트에서는 실제 구조와 지침을 먼저 조사하도록 한다.
4. Codex와 Gemini/Antigravity에 같은 의미의 작업 기준을 연결한다.
5. 기존 사용자 파일과 스킬을 보존하면서 관리 영역만 갱신한다.
6. 검토된 외부 스킬을 출처와 라이선스 정보와 함께 사용할 수 있게 한다.
7. 반복해서 가치가 입증된 작업 방식을 버전이 있는 지능 자산으로 배포한다.

### 책임 범위

- 공통 개발 원칙과 프로젝트 진입 정책 관리
- 재사용 가능한 자체 스킬 패키징
- 외부 스킬 소스와 법적 고지 관리
- 에이전트별 지침 파일 생성과 관리 블록 갱신
- 프로젝트별 스킬 설치, 충돌 방지와 관리 대상 추적
- 설치 결과의 출처, 버전과 검증 가능성 제공
- npm 배포와 회귀 테스트

현재 공개 버전은 하나의 대화형 초기화 흐름을 제공한다. `init`, `update`, `status`, `uninstall`으로 수명주기를 분리하는 것은 이 프로젝트 안에서 설계하고 검증할 다음 목표이며 현재 기능으로 간주하지 않는다.

### 책임 범위가 아닌 것

- 파운데이션 모델의 학습이나 호스팅
- 작업별 모델 자동 선택과 API 호출
- 사내 문서 전체의 저장과 검색
- 대화 기록 전체의 장기 기억
- 벡터 데이터베이스와 검색 서비스 운영
- 특정 프로젝트의 코드와 도메인 지식을 공통 패키지에 복제
- 여러 독립 프로젝트의 전체 로드맵 관리

## 지능 자산의 위치 원칙

| 자산 | 현재 위치 | 장기 소유 위치 |
|---|---|---|
| 공통 개발 원칙 | `rules/` | 이 프로젝트 |
| 재사용 가능한 자체 스킬 | `bundled-skills/` | 이 프로젝트 |
| 외부 공개 스킬 목록 | `skill-sources.json` | 이 프로젝트 |
| 프로젝트 전용 구조와 계약 | 각 대상 프로젝트 | 각 대상 프로젝트 |
| 조직 공통 비공개 지식 | 아직 없음 | 향후 비공개 컨텍스트 프로젝트 |
| 전체 비전·아키텍처·로드맵 | 이 문서 | 향후 상위 전략 프로젝트 |
| 평가 시나리오와 개선 지표 | 아직 없음 | 이 저장소에서 시작한 뒤 상위 전략 프로젝트로 이전 |
| 모델 선택과 비용 정책 | 아직 없음 | 필요성이 확인되면 모델 실행 프로젝트 |
| 대규모 문서 검색과 장기 기억 | 아직 없음 | 필요성이 확인되면 컨텍스트 검색 프로젝트 |

새로운 지식은 가장 좁고 정확한 소유 위치에 둔다. 특정 프로젝트에만 유효한 지식을 공통 npm 패키지에 넣지 않으며, 비공개 정보와 인증 정보는 공개 패키지에 포함하지 않는다.

이 프로젝트의 공통 의미는 `rules/`, `bundled-skills/`와 `skill-sources.json`을 단일 원천으로 삼는다. `AGENTS.md`, `GEMINI.md`와 Antigravity 규칙 파일은 에이전트별 전달 형식이며 별도의 규칙 원본이 아니다. 생성 과정은 기존 사용자 내용을 보존하고 관리 블록만 갱신한다. 실제 작업에서는 사용자 요청과 실행 환경의 상위 지침을 우선하고, 저장소 지침끼리 충돌하면 작업 파일에 더 가까운 범위를 적용한다.

현재 저장소의 테스트는 CLI 구현의 회귀를 검증한다. 전체 시스템의 품질 평가 시나리오와 합격 기준은 아직 존재하지 않으며, 처음 정의할 때는 이 문서와 같은 저장소에서 관리하고 상위 전략 프로젝트가 생성되면 함께 이전한다.

## 향후 프로젝트 후보

다음 항목은 현재 구현된 프로젝트가 아니라 실제 필요가 확인될 때 분리할 개념이다. 이름과 기술은 생성 시점에 다시 결정한다.

### 상위 전략 프로젝트

전체 시스템의 비전, 아키텍처, 거버넌스, 로드맵, 구성요소 목록과 평가 기준을 관리한다. 생성되면 이 문서의 전체 전략 부분을 그 저장소로 이전하고, 각 하위 프로젝트는 자신의 책임과 연계 계약만 관리한다.

### 비공개 컨텍스트 프로젝트

조직 공통 아키텍처, 보안 정책, 도메인 용어와 사내 재사용 스킬 및 접근 권한을 관리한다. 공개 `ai-init` 패키지와 분리한다. 연계가 필요해지면 비공개 프로젝트가 데이터와 권한을 소유하고, 이 프로젝트는 승인된 형식의 설치 연결 기능만 담당한다.

### 컨텍스트 검색 프로젝트

코드와 문서의 규모 때문에 직접 탐색만으로 필요한 정보를 찾기 어려워졌을 때 인덱싱, 검색, 출처 표시와 접근 제어를 담당한다. 벡터 데이터베이스나 RAG는 이 문제가 실제로 확인된 뒤 선택한다.

### 모델 실행 프로젝트

작업 성격, 품질, 비용과 속도에 따라 모델을 선택할 필요가 생겼을 때 모델 호출, 라우팅, 장애 대체와 사용량 관측을 담당한다.

## 프로젝트 간 연계 원칙

향후 프로젝트가 생성되면 이름만 나열하지 않고 다음 세 계약을 함께 정의한다.

### 개념적 연계

- 각 프로젝트가 전체 목표의 어느 문제를 해결하는지 정의한다.
- 같은 개념을 여러 저장소가 서로 다르게 정의하지 않도록 단일 원천을 지정한다.
- 상위 전략과 하위 구현의 관계를 문서 링크로 연결한다.

### 역할적 연계

- 입력과 출력의 소유자를 정한다.
- 공개·비공개 정보의 경계를 정한다.
- 변경 승인, 배포와 장애 대응 책임을 정한다.
- 한 프로젝트의 책임이 다른 프로젝트로 새지 않도록 비책임 범위를 기록한다.

### 기능적 연계

- 파일 형식, 버전, 명령 또는 API 계약을 정의한다.
- 호환되는 최소 버전과 실패 시 동작을 정의한다.
- 설치·업데이트·검증·제거 흐름을 함께 시험한다.
- 연결된 버전과 출처를 사용자가 확인할 수 있게 한다.

## 성장 순환

```text
실제 프로젝트 작업
  → 성공, 실패 또는 반복 문제 발견
  → 재사용 가치와 적용 범위 검토
  → 가장 적절한 단일 원천에 반영
  → 검증 시나리오로 효과 확인
  → 필요한 프로젝트와 에이전트에 재배포
```

모든 대화 내용을 자동으로 자산화하지 않는다. 반복 가능성, 다른 프로젝트에서의 효용, 기존 규칙과의 충돌, 실제 행동 변화와 검증 가능성을 확인한 내용만 반영한다.

## 현재 단계의 운영 원칙

1. 지금은 이 저장소가 유일한 구현 프로젝트이며 이 문서가 전체 개념의 임시 기준이다.
2. 실제 개발 우선순위는 현재 CLI의 안전한 설치·업데이트·상태 확인·제거와 재현성 확보다.
3. 미래 프로젝트의 디렉터리나 코드를 이 저장소에 미리 만들지 않는다.
4. 별도 프로젝트는 실제 문제, 데이터 또는 운영 책임이 생겼을 때 생성한다.
5. 새 프로젝트가 생기면 먼저 개념적·역할적·기능적 연계 계약을 작성한 뒤 구현을 연결한다.
6. 상위 전략 프로젝트가 생기면 전체 구조의 단일 원천을 그곳으로 옮기고, 이 저장소에는 `ai-init`의 목적·책임·인터페이스만 유지한다.

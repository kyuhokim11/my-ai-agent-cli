# New Project Entry Policy

이 모드는 사용자가 CLI에서 신규 프로젝트를 선택했을 때 적용된다. 이미 요청과 대화에서 확인되는 목적이나 조건을 다시 묻지 않는다.

1. 구현 전에 목적, 사용자, 성공 조건과 이번 작업 범위를 명확히 한다.
2. 구조와 도구는 현재 요구사항을 충족하고 검증할 수 있는 범위에서 선택한다. 새로운 프레임워크·라이브러리가 필요하면 이유·대안·영향을 계획에 포함하고, 미정 요구를 위한 계층이나 확장을 미리 추가하지 않는다.
3. 플랫폼·언어 기본 기능과 기존 도구를 우선 검토하되, 변경량이나 도구 수만으로 더 적합한 해결책을 배제하지 않는다.
4. 최초 구조는 성공 조건, 유지보수성과 이후 변경 비용을 고려해 정하고 검증 가능한 단위로 구현한다. 계획 변경과 규칙 충돌은 공통 규칙의 피드백 기준을 따른다.
5. 아직 결정되지 않은 API, 환경 변수와 배포 조건을 임의로 확정하지 않는다.
6. 기록이 필요한 작업은 기존 README 등에서 확인된 목표와 범위를 원본으로 삼는다. 기록 체계가 없으면 `jobkim-project-context`의 예시 중 필요한 부분만 계획에 포함한다. 미래 구조나 미정 요구를 사실로 기록하지 않는다.
